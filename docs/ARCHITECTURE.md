# AgentOS 终端 Agent：结构框架

对照成熟 agent（Claude Code / Codex / Aider / OpenHands / SWE-agent）的**结构**逐层对齐，
说明每一层干什么、我们怎么做的、缺什么。终端专用：没有网页面、没有原生 app、没有常驻服务。

```
┌─ 入口层 ───────────────────────────────────────────────────────┐
│ agentos agent            REPL（多行输入 / @补全 / 斜杠命令）      │
│ agentos agent -p '…'     headless 一次跑完，退出码可接 CI           │
│ 过程显示：Claude Code 式（⏺ Write(x) / ⎿ 结果 / 一行状态）        │
└─────────────────────────────────────────────────────────────────┘
┌─ 会话层 ────────────────────────────────────────────────────────┐
│ ctx = {root, mode, sid, history, evo_rules_path, task_contract}  │
│ 历史压缩 v2：丢弃前先让模型写事实摘要 digest，失败逐字回退旧口径     │
│ 预算感知压缩：配了 llm.context_window 就按 token 预算规划，         │
│   R1 用户的 ask 永不丢 · R2 尾巴连续不挖洞 · R3 保底装不下就拒压缩   │
│ 会话分支 / 回放：/branch /resume /rewind（落 transcript，可重放）   │
└─────────────────────────────────────────────────────────────────┘
┌─ 计划层 ────────────────────────────────────────────────────────┐
│ DSP：需求 → 结构化分析（SMALL/BIG）→ 里程碑 → 任务 DAG → 派发      │
│   未审批写锁死（/approve 才放行）、任务工具白名单、DoomWatch 循环检测 │
│ 任务账本 todo：agent 自己列步骤、逐项勾；**有 pending 不许说「做完了」** │
│   账本是**任务域模型**（学 ruflo v3 的 Task 实体）：带守卫的状态迁移      │
│   （done 不许打回 pending，重开要写理由并留痕）· 依赖+就绪+环检测         │
│   （面板标「等 #2」· 成环拒绝）· 优先级（就绪项 high 先做）              │
└─────────────────────────────────────────────────────────────────┘
┌─ 执行层 ────────────────────────────────────────────────────────┐
│ 工具面：read/write/edit · run_cmd · list/search · git 三件套         │
│         gh 四件套（search/repo_view/file_read）· web_fetch · subagent│
│         todo（记账）· skills · MCP 注入                            │

┌─ 证据层（本仓与多数 agent 的差别就在这层）────────────────────────┐

│ 任务契约 task_contract：按任务类型要求**不同**的完成证据             │

│ 证据只认证据不认措辞：写「已修复」不算，跑出 rc=0 才算               │

┌─ 进化层 ────────────────────────────────────────────────────────┐
│ 信号账 signals.jsonl（每轮一条：工具/成败/耗时/收敛痕迹/契约类型）    │

└─────────────────────────────────────────────────────────────────┘
```

打 ✅ 的不是「也有个差不多的」，而是**这一层能独立证伪**（每层都有门/自检盯着）。

## 三条贯穿全层的纪律

1. **证据只认证据，不认措辞。** 终答里写「已修复 / 已完成 / 已部署」不算；
   要有 `write` 成功、`run_cmd rc=0`、读回的内容、或者 `git diff` 看过。
2. **不许拿没验证过的结果当完成。** 交付闸是 fail-closed：证据不足 → 退回补证据；
   预算用尽 → **判未交付**（不假装成功）。任务账本有 pending → 同样不许交。
3. **失败必须说在明处。** 没跑的命令、没验证的结论、跳过的部分，写进终答；
   但终答本身要短（3-6 行），不许用「罗列没做到的部分」把长报告伪装成诚实。

## 已知缺口（下一轮候选）

- **失败的自动修复回路（已实装 2026-10-21，见下）**：核对红时不再只说「不许交」——
  `tools/converge.py` 的有界修复回路把失败记成 `{cmd, rc, tail}`，下一步给模型一条
  可定位指令（哪条命令 / rc / 输出尾部，截断），修好后旧记录作废；配额 `max_fix_hints`
  （默认 3，钳在 1..5）用尽即 `fix_suppressed`，不再催。仍缺的是**跨轮**的失败模式
  沉淀（现在是单轮账本 `snapshot().fix_failures`，还没喂给自进化挖掘）。
- **子代理的账本与契约继承**：子代理现在继承 ctx，但不继承任务契约与 todo。
- **回放语料的覆盖面**：现在 4 条真实语料，够证伪但不够当基准用。
- **跨会话记忆的检索**：记忆是整段注入，没有按相关性检索。
